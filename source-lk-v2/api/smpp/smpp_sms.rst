SMS
====

Запрос на отправку 
=========================

Для отправки сообщения Партнёру следует :ref:`установить соединение <linkSetting>` с сервером и передать Сервис-провайдеру пакет ``submit_sm``, 
в котором содержатся все необходимые параметры сообщения (опционально, также и :abbr:`TLV (Tag Length Value)`-параметры).

.. note:: При необходимости использования дополнительного функционала следует указать значения соответствующих TLV-параметров, описание которых приведено в следующих разделах сайта:

          - :doc:`smpp_cascade`;
          - :doc:`smpp_short_link`.

|                           |                          | | Кодировка значения параметра ``source_addr`` (согласно протоколу SMPP): ASCII.                           |
+---------------------------+--------------------------+------------------------------------------------------------------------------------------------------------+

+---------------------------+--------------------------+------------------------------------------------------------------------------------------------------------+
| short_message             | string                   | | Текст сообщения для отправки абоненту.                                                                   |

|                           |                          | | Длина пользовательских данных для поля ``short_message``, не более: 254 октета.                          | 
|                           |                          | | Длинные текстовые сообщения (длиннее, чем 254 октета, многосегментные с точки зрения SMPP)               |
|                           |                          |   рекомендуется передавать одной PDU, отправляя текст в TLV-параметре ``message_payload``, id = 0x0424.    | 
|                           |                          |   Данные сообщения следует вставлять или в поле ``short_message``, или в поле ``message_payload``.         |
|                           |                          |   **Внимание!** Одновременное использование обоих полей недопустимо. При использовании поля                |
|                           |                          |   ``message_payload`` поле ``short_message`` должно оставаться пустым.                                     |
|                           |                          | | SMPP-сервер Сервис-провайдера поддерживает склейку сообщений, разбитых на части,                         | 
|                           |                          |   одним из следующих методов:                                                                              |
|                           |                          |                                                                                                            | 
|                           |                          | - UDH-8;                                                                                                   |

|                           |                          | | Допустимые значения:                                                                                     |
|                           |                          |                                                                                                            |
|                           |                          | - 0 – DEFAULT, кодировка по умолчанию;                                                                     |

|                           |                          | - 1 – Партнёру требуется уведомление о статусе доставки;                                                   |

|                           |                          |                                                                                                            |

|                           |                          |   она не может быть позже определённого срока с текущего момента.                                          |

| message_payload           | Tag                 | 2                 | Integer           | id = 0x0424                                                           |
|                           +---------------------+-------------------+-------------------+-----------------------------------------------------------------------+
|                           | Length              | 2                 | Integer           | Длина параметра в октетах.                                            |
|                           +---------------------+-------------------+-------------------+-----------------------------------------------------------------------+
|                           | Value               | до 2048           | Octet String      | Текст сообщения длиной более 254 октетов.                             |
|                           |                     |                   |                   |                                                                       |
|                           |                     |                   |                   | | Текст сообщения следует вставлять либо в поле ``short_message``,    |
|                           |                     |                   |                   |   либо в поле ``message_payload``.                                    |
|                           |                     |                   |                   | | Одновременное использование обоих полей недопустимо.                |
|                           |                     |                   |                   | | При использовании поля ``message_payload`` поле ``short_message``   |
|                           |                     |                   |                   |   должно оставаться пустым.                                           |
+---------------------------+---------------------+-------------------+-------------------+-----------------------------------------------------------------------+
| ptag                      | Tag                 | 2                 | Integer           | id = 0x1411                                                           |
|                           +---------------------+-------------------+-------------------+-----------------------------------------------------------------------+
|                           | Length              | 2                 | Integer           | Длина параметра в октетах.                                            |
|                           +---------------------+-------------------+-------------------+-----------------------------------------------------------------------+
|                           | Value               | до 1000           | Octet String      | Идентификатор сообщения в системе Партнёра.                           |
|                           |                     |                   |                   |                                                                       |
|                           |                     |                   |                   | | Может содержать от 1 до 50 символов.                                |
|                           |                     |                   |                   | | Допустимые символы: 0...9a...zA...Z-.                               |
|                           |                     |                   |                   | | Это может быть любой идентификатор в системе Партнёра.              |
|                           |                     |                   |                   | | Например, уникальный идентификатор сообщения или идентификатор      |
|                           |                     |                   |                   |   подразделения, инициирующего запрос на отправку.                    |
|                           |                     |                   |                   | | Сервис-провайдер не контролирует значения, переданные в параметре   |
|                           |                     |                   |                   |   ``ptag`` (проверяется только соответствие формату).                 |
|                           |                     |                   |                   |   Сервис-провайдер опционально возвращает Партнёру данный             |

|                           |                     |                   |                   |   (см. :doc:`smpp_status`).                                           |

Ответ на запрос 
================

На пакет ``submit_sm`` сервер Сервис-провайдера отвечает пакетом ``submit_sm_resp`` с полем ``command_status``.

Если пакет принят и обработан успешно, тело пакета ``submit_sm_resp`` будет содержать ``message_id`` — уникальный идентификатор (целое положительное число), 
присвоенный на сервере Сервис-провайдера данному PDU. 

В дальнейшем значение ``message_id`` используется Партнёром для получения и анализа статусов доставки сообщения.

Возможные значения поля ``command_status`` приведены в таблицах ниже.

Ответ при успешной отправке
----------------------------

В случае успешной отправки возвращается код ответа (HEX) ``0x00``.
          
+---------------------+-----------------------------------------------------+---------------------------------------------------------+
| Код (HEX)           | Описание                                            | Действие Партнёра                                       |
+=====================+=====================================================+=========================================================+
| 0x00                | Пакет принят успешно.                               | Ошибок нет, штатная работа сервиса.                     |
+---------------------+-----------------------------------------------------+---------------------------------------------------------+

----------------------

Для ошибочных результатов код ответа (HEX) будет отличный от ``0x00``.

|                     |                                                     | повторить попытку отправки сообщения.                   |

| 0x03                | Партнёр передал PDU неподдерживаемого типа          | Партнёр устраняет ошибки на своей стороне.              |
|                     | (query_sm, submit_multi, data_sm и т.п.).           |                                                         |
+---------------------+-----------------------------------------------------+---------------------------------------------------------+
| 0x08                | Общая системная ошибка на сервере.                  | | Партнёр может повторить попытку отправить сообщение.  |
|                     |                                                     | | Если ошибка повторяется, следует прекратить попытки   |
|                     |                                                     |   отправить сообщение и обратиться в                    |
|                     |                                                     |   :ref:`Службу технической поддержки <support>`,        |
|                     |                                                     |   предоставив наиболее полную информацию                |

| 0x0A                | | Неверное имя отправителя.                         | Партнёр устраняет ошибки на своей стороне, после этого  |
|                     | | Партнёр передал в параметре ``source_addr``       | может повторить отправку сообщения с корректным         |
|                     |   значение, с которого не разрешена отправка        | ``source_addr``.                                        |
|                     |   сообщений абонентам.                              |                                                         |
+---------------------+-----------------------------------------------------+---------------------------------------------------------+
| 0x0B                | | Неверный номер получателя.                        | | Партнёр не должен повторять отправку сообщения.       |
|                     | | Попытка отправить сообщение на номер,             | | Партнёру следует обратиться к менеджеру               |

| 0x0C                | Передано некорректное значение TLV-параметра ptag   | Партнёр исправляет значение параметра и может повторить |

+---------------------+-----------------------------------------------------+---------------------------------------------------------+
| 0x14                | | Очередь на отправку сообщений от Партнёра         | | Партнёр приостанавливает процесс отправки SMS         |

|                     | | Пример. Для сервиса Партнёра установлено          | | Партнёр может повторить отправку сообщений, на        |

============================

Для получения статусов SMS-сообщений необходимо настроить :doc:`smpp_status`.


SMS-сессии
=============

Функционал сессий для SMS-сообщений позволяет абоненту пользоваться сервисом, не ограничивая сообщения ключевыми словами.

Открытие сессии происходит при отправке абонентом на сервисное имя сообщения с ключевым словом для открытия сессии.  

Все сообщения с кодовым словом или сообщения, попавшие в сессию, передаются Партнёру. 

В ответ абоненту передается текст, предоставленный Партнёром.

Временной интервал активной сессии прописан в конфигурации сервиса. В течение этого интервала времени все сообщения, присланные абонентом на данное сервисное имя, 
будут обрабатываться сессионным сервисом. Продление времени сессии происходит при отправке абонентом сообщения, если в момент отправки сообщения сессия 
на сервисном имени активна. В этот момент сообщение может содержать любой текст, кроме команды выхода из сессии. Сессия продлевается на время
активности сессии, установленное в конфигурации сервиса.

Время активной сессии истекает, если абонент за данный временной период не прислал ни одного сообщения на сервисное имя. По истечении времени активности сессии, 
абоненту приходит сообщение (опционально), оповещающее его о том, что время сессии истекло и она закрывается. 

Абонент может самостоятельно закрыть сессию. Для этого ему необходимо отправить ключевое слово выхода из сессии. В ответ абоненту придет сообщение, 
подтверждающее закрытие сессии, и сессия завершается.


Подключение 
----------------

Для подключения функционала SMS-сессий Партнёр должен дополнительно сообщить менеджеру Сервис-провайдера следующие данные:

1. Желаемое ключевое слово с синонимами (регулярное выражение) для открытия сессии.
2. Нужно ли Сервис-провайдеру отвечать абоненту на ключевое слово при открытии сессии. Если «да», то необходимо предоставить текст сообщения, отправляемый абоненту при открытии сессии.
3. Желаемое ключевое слово с синонимами (регулярное выражение) для закрытия сессии. Ключевое слово для закрытия сессии может отсутствовать или быть одинаковым для всех сервисов Партнёра.
4. Нужно ли Сервис-провайдеру отвечать абоненту на ключевое слово при закрытии сессии. Если «да», то необходимо предоставить текст сообщения, отправляемый абоненту при закрытии сессии.
5. Интервал времени, в течение которого сессия будет активна.
6. Текст сообщения, высылаемый абоненту в случае недоступности сервера Партнёра.
