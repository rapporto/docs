# Docs

Документация ЛК Раппорто.

## Инструкция по работе с проектом

### 1. Структура проекта

Проект использует CI/CD с двумя основными этапами:

- **build**: Сборка документации с помощью Sphinx.
- **deploy**: Деплой собранной документации на тестовый или продакшн сервер.

### 2. Ветки проекта

- **test**: Ветка для тестирования изменений. Деплой происходит на тестовый сервер.
- **main**: Основная ветка для продакшн. Деплой на продакшн сервер.

### 3. Работа с ветками

#### Создание новой ветки

1. Создайте новую ветку от `main` или `test`:

   ```bash
   git checkout -b feature/your-feature-name
   ```

2. Внесите необходимые изменения:

   ```bash
   git add .
   git commit -m "Добавлена новая функция"
   ```

3. Отправьте ветку на сервер:

   ```bash
   git push origin feature/your-feature-name
   ```

#### Создание Merge Request (MR)

1. Перейдите в интерфейс GitLab и создайте Merge Request из вашей ветки в `test`
2. Убедитесь, что все проверки CI/CD проходят успешно.
3. После одобрения MR, выполните слияние.

### 4. Деплой на тестовый сервер

После слияния изменений в ветку `test`:

- CI/CD автоматически запустит процесс сборки и деплоя на тестовый сервер.

### 5. Деплой на продакшн сервер

Для деплоя на продакшн сервер:

1. Убедитесь, что все изменения протестированы в ветке `test`.
2. Создайте Merge Request из `test` в `main`.
3. После одобрения и слияния, CI/CD автоматически запустит процесс сборки и деплоя на продакшн сервер.

### 6. Процесс сборки и деплоя

#### Сборка

При запуске этапа `build` выполняются следующие действия:

- Установка необходимых пакетов Sphinx.
- Сборка документации с помощью команды `sphinx-build`.

#### Деплой

При запуске этапа `deploy` выполняются следующие действия:

- Установка клиента SSH и настройка ключей для доступа к серверам.
- Использование `rsync` для копирования собранной документации на целевой сервер.

### 7. Переменные окружения

Для корректной работы CI/CD необходимо настроить следующие переменные окружения в GitLab:

- `TEST_LK_V1_SSH_KEY`: SSH-ключ для доступа к тестовому серверу
- `TEST_LK_V1_SERVER`: Адрес тестового сервера <https://doc-test.rapporto.ru/>
- `PROD_LK_V1_SSH_KEY`: SSH-ключ для доступа к продакшн серверу
- `PROD_LK_V1_SERVER`: Адрес продакшн сервера <https://doc.rapporto.ru/>
- `TEST_LK_V2_SSH_KEY`: SSH-ключ для доступа к тестовому серверу
- `TEST_LK_V2_SERVER`: Адрес тестового сервера <https://docs-test.rapporto.ru/>
- `PROD_LK_V2_SSH_KEY`: SSH-ключ для доступа к продакшн серверу
- `PROD_LK_V2_SERVER`: Адрес продакшн сервера <https://docs.rapporto.ru/>
- `USER`: Имя пользователя для SSH-доступа
- `GITHUB_REPO`: Внешний репозиторий GitHub
- `GITHUB_TOKEN`: Токен для внешнего репозитория GitHub
