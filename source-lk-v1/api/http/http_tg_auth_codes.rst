Коды авторизации Telegram Gateway
==================================

В данном разделе приведено описание особенностей передачи авторизационных кодов по протоколу HTTP в Telegram Gateway. 

.. raw:: html

     <details>
         <summary>Подробнее</summary>
         <p>
             Сервис Telegram Gateway предназначен для доставки пользователям мессенджера Telegram авторизационных и верификационных цифровых кодов.
         </p>
         <p>
             Отправка кодов происходит от имени официального канала Verification Codes.
         </p>
         <p>
             Если пользователь скрывает свой номер телефона в настройках Telegram, это не влияет на доставку сообщения.
             Также на доставку кодов не влияет наличие или отсутствие у пользователя подписки Telegram Premium.
         </p>
         <p>
             Отправка цифровых кодов в Telegram возможна в текстах сообщений типа SMS. В процессе обработки сообщения будут конвертированы в TG-формат и переданы в Telegram. 
         </p>
         <p>
             На данный момент сервис поддерживает:
         </p>
         <ul>
             <li>отправку сообщений с кодами авторизации через Telegram;</li>
             <li>получение статусов доставки сообщений;</li>
             <li>каскадную передачу сообщений в SMS в случае недоставки в Telegram (при необходимости).</li>
         </ul>  
     </details>


Подключение 
---------------

Подключение сервиса осуществляет :ref:`служба технической поддержки <support>` Сервис-провайдера. 

Для подключения Партнеру и Сервис-провайдеру необходимо согласовать данные:

- сервисное имя для передачи авторизационного кода в Telegram;
- время жизни сообщения.


Запрос на отправку 
-------------------

В запросе на передачу авторизационного кода в Telegram необходимо указывать сервисное имя, отдельно согласованное со :ref:`службой технической поддержки <support>`.

В запросе рекомендуется указать параметры и значения, относящиеся к типу сообщения ``SMS``.

Сообщение должно содержать код от четырёх до восьми цифр.

Допустимые типы данных при передаче запроса:

- текстовые данные -- передаются как текстовое сообщение;
- двоичные данные -- передаются в теле сообщения. 


Примеры запросов
~~~~~~~~~~~~~~~~~~~~

В HTTP API допустимы POST и GET запросы.

.. tabs::

    .. tab:: POST-запросы

        .. tabs::

            .. tab:: Текстовый формат

                POST-запрос с текстом сообщения на латинице ``code 12345`` в простом текстовом формате:

                .. code-block::

                    POST /<uri> HTTP/1.1
                    Host: 10.10.10.10:9080
                    Content-Type: application/x-www-form-urlencoded;charset=utf-8
                    Content-Length: 78
                    serviceId=login&pass=123&clientId=79161234567&message=code 12345

                
                Описание формата запроса:

                - POST /login HTTP/1.1: URI запроса;
                - Host: Адрес и порт сервера;
                - Content-Type: Тип контента;
                - Content-Length: Длина тела запроса. В данном случае длина строки ``serviceId=login&pass=123&clientId=79161234567&message=code 12345`` равна 78.
                - Тело запроса: Содержит параметры в простом текстовом формате.


            .. tab:: Текст в URL-формате

                POST-запрос с текстом сообщения на кириллице ``код 12345`` в URL-формате:

                .. code-block::

                    POST /login HTTP/1.1
                    Host: 10.241.0.194:9080
                    Content-Type: application/x-www-form-urlencoded;charset=utf-8
                    Content-Length: 80
                    serviceId=login&pass=123&clientId=79161234567&message=%D0%BA%D0%BE%D0%B4+12345

                Описание формата запроса:

                - POST /login HTTP/1.1: URI запроса;
                - Host: Адрес и порт сервера;
                - Content-Type: Тип контента;
                - Content-Length: Длина тела запроса. В данном случае длина строки ``serviceId=login&pass=123&clientId=79161234567&message=%D0%BA%D0%BE%D0%B4+12345`` равна 80.
                - Тело запроса: Содержит параметры, включая URL-кодированное сообщение "код 12345", где пробел заменен на ``+`` и кириллические символы закодированы в UTF-8.

            .. tab:: Текстовый формат

                    http://partner.ru/login?serviceId=login&pass=123&clientId=79161234567&message=code%2012345

Запросы  с двоичными данными
------------------------------------

При передаче двоичных данных в тексте сообщения передается последовательность байт в шестнадцатеричной системе счисления.

Для передачи двоичных данных в POST или GET запросе необходимо указать дополнительные параметры, указанные в таблице ниже.

Примеры запросов
~~~~~~~~~~~~~~~~~~~

.. tabs::

    .. tab:: POST-запрос

        POST-запрос с текстом сообщения на кириллице ``код 12345`` в виде последовательности байт в шестнадцатеричной системе счисления в кодировке UTF-8.

        .. code-block::
       
            POST /login HTTP/1.1
            Host: 10.241.0.194:9080
            Content-Type: application/x-www-form-urlencoded;charset=utf-8
            Content-Length: 144
            serviceId=login&pass=123&clientId=79161234567&message=D0BAD0BED0B4203132333435&smpp_encoding=245&smpp_esm_class=64


    .. tab:: GET-запрос

        GET-запрос с текстом сообщения на кириллице ``код 12345`` в виде последовательности байт в шестнадцатеричной системе счисления в кодировке UTF-8.

        .. code-block::

            http://partner.ru/login?serviceId=login&pass=123&clientId=79161234567&message=D0BAD0BED0B4203132333435&smpp_encoding=245&smpp_esm_class=64 HTTP/1.1
            
        .. note::

            В GET-запросе параметры передаются в строке запроса, и пробелы заменяются на ``%20``, а специальные символы должны быть закодированы.

.. _tg-codes-Ответ на запрос:

Ответ на запрос 
----------------------

| После получения и обработки запроса Сервис-провайдер синхронно возвращает Партнёру ответ. 
| По умолчанию ответ от Сервис-провайдера приходит в формате :abbr:`text/plain (Простой текст)`.
| По согласованию с Партнёром ответ может быть сформирован в формате :abbr:`XML (Xtensible Markup Language - расширяемый язык разметки)`. 


.. note:: Сервис-провайдер отправляет сообщения абонентам только при успешной обработке запроса.

        |               |   сообщению Сервис-провайдером.                           |                                                           |

.. _SMS Ответ в формате XML:

Ответ в формате XML
~~~~~~~~~~~~~~~~~~~~

| Для получения ответа в формате :abbr:`XML (Xtensible Markup Language — расширяемый язык разметки)` Партнеру в теле запроса необходимо передать параметр ``output=xml``.
| В таком случае Сервис-провайдер синхронно отвечает на запрос одним из следующих HTTP-кодов:

* ``200`` – запрос успешно обработан;
* ``500`` – внутренняя ошибка сервера, технические проблемы на стороне Сервис-провайдера.

Примеры ответов
^^^^^^^^^^^^^^^^^^

.. tabs::

    .. tab:: Успешная отправка

        Пример ответа в формате XML при успешной отправке запроса (HTTP-код ``200``) .

        .. code-block::

            <?xml version="1.0" encoding="utf-8"?>
            <response>
                <code>200</code>
                <text>OK</text>
                <payload>
                    <id>4095284976</id>
                </payload>
            </response>
            


    .. tab:: Отправка с ошибкой

        Пример ответа в формате XML при ошибочной отправке запроса: неверное сочетание ``serviceId/pass``.

        .. code-block::

            <?xml version="1.0" encoding="utf-8"?>
            <response>
                <code>401</code>
                <text>Invalid password</text>
            </response>
            

        При получении статуса ``500`` или при истечении тайм-аута ожидания ответа, Партнёр должен выдержать паузу минимум одну минуту. По истечении паузы Партнёр может повторить запрос.

        .. note:: При получении статуса ``500`` более 10 раз необходимо прекратить передачу запроса. После чего передать в службу техподдержки Сервис-провайдера наиболее полную информацию об условиях возникновения данной ошибки для дальнейшего анализа.

Каскадная отправка
--------------------

:term:`Каскадная рассылка` сообщений по умолчанию недоступна. Для подключения и настройки Партнёру необходимо 
обратиться в :ref:`службу технической поддержки <support>` Сервис-провайдера.

Порядок и опции доотправки могут быть настроены на стороне Сервис-провайдера по заявке от Партнёра. В таком случае доотправка сообщений происходит с параметрами, 
заданными по умолчанию, и в теле запроса *не требуется передавать* никаких дополнительных параметров.

Также есть возможность передавать опции каскада, используя дополнительные параметры HTTP-запроса.

.. important::
